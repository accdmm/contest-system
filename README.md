# 高校学科竞赛报名管理系统

基于 Spring Boot 3 + Vue 3 + MySQL 的全栈高校竞赛报名管理系统。支持个人/团队竞赛报名、管理员审核流程、内容管理（CMS）以及 AI 智能助手。

## 功能特性

### 学生功能

| 功能 | 说明 |
|------|------|
| **浏览竞赛** | 查看所有竞赛，支持关键字搜索、类别筛选、分页 |
| **竞赛详情** | 富文本描述、时间地点、参赛形式、人数限制 |
| **个人报名** | 报名个人赛，可附加备注 |
| **团队管理** | 创建团队、生成6位邀请码、邀请队友 |
| **团队报名** | 队长提交通过审核的团队进行竞赛报名 |
| **报名追踪** | 查看报名记录及审核状态（待审核/已通过/已驳回/已取消） |
| **通知收件箱** | 实时接收审核结果、入队申请、系统公告等通知 |
| **个人设置** | 编辑资料、修改密码、配置通知偏好 |
| **AI 助手** | 与 AI 对话，可查询竞赛、检查报名状态、执行报名操作 |

### 管理员功能

| 功能 | 说明 |
|------|------|
| **竞赛管理** | 创建、编辑、发布/下架、删除竞赛 |
| **报名审核** | 通过或驳回报名申请（需填写驳回原因） |
| **团队审核** | 通过或驳回团队（驳回时自动取消关联的报名） |
| **用户管理** | 查看/创建用户、编辑资料、冻结/解冻账号；支持学生/教师/管理员三种角色 |
| **内容管理** | 管理首页轮播图和公告（富文本编辑器） |
| **权限管理** | 按角色或按用户分配权限（细粒度权限控制） |
| **通知管理** | 发送定向通知或系统广播 |
| **操作日志** | 查看管理员操作审计记录 |

### AI 助手功能

AI 助手（基于 DashScope glm-5.1 模型）提供 7 个调用工具：

| 工具 | 说明 |
|------|------|
| `getCurrentUserInfo` | 获取当前登录用户信息 |
| `queryContests` | 浏览竞赛列表（关键字/类别筛选） |
| `searchContestDetail` | 按名称搜索特定竞赛 |
| `registerForContest` | 报名个人竞赛 |
| `createTeamForContest` | 创建团队参加竞赛 |
| `queryMyRegistrations` | 查询本人的报名记录 |
| `queryMyTeams` | 查询本人创建或加入的团队 |

AI 助手支持 SSE 流式对话、对话历史持久化。系统提示词强制助手如实返回工具调用结果，禁止编造答案。

## 数据库设计

系统使用 `contest_system` 数据库，共 10 张表：

| 表名 | 说明 | 关键字段 |
|------|------|----------|
| `user` | 用户表（学生 + 教师 + 管理员） | id, username（学号）, password（BCrypt）, name, role（0=学生, 1=管理员, 2=教师）, college, major, class_name, status |
| `contest` | 竞赛表 | id, name, category, level, organizer, contest_time, register_start/end_time, location, contest_type（0=个人, 1=团队, 2=两者皆可）, team_min/max_size, max_participants, status, current_count |
| `team` | 团队表 | id, leader_id, team_name, team_no（唯一编号）, invite_code（6位）, status（0=组建中, 1=已提交, 2=已通过, 3=已驳回）, member_count |
| `team_member` | 团队成员关系表 | id, team_id, user_id, role（0=成员, 1=队长）, status（0=待审核, 1=已通过, 2=已拒绝） |
| `registration` | 报名记录表 | id, contest_id, user_id, team_id, reg_type, status（0=待审核, 1=已通过, 2=已驳回, 3=已取消） |
| `notification` | 消息通知表 | id, user_id（0=广播）, type, title, content, related_id, related_type, is_read |
| `cms_content` | 内容管理表 | id, content_type（0=轮播图, 1=公告）, title, content, image_url, sort_order, position, publish_time |
| `operation_log` | 操作日志表 | id, user_id, action, detail, ip_address |
| `ai_conversation` | AI 对话会话表 | id, user_id, title |
| `ai_message` | AI 对话消息表 | id, conversation_id, role（user/assistant）, content, tokens |

## 快速开始

### 环境要求

- Java 17+
- Maven 3.6+
- Node.js 18+
- MySQL 5.7+ / 8.0
- （可选）DashScope API 密钥（用于 AI 助手）
- （可选）MinIO（用于文件存储，默认使用本地文件系统）

### 1. 初始化数据库

```bash
mysql -u root -p < contest-system/sql/init.sql
mysql -u root -p < contest-system/sql/seed.sql
```

### 2. 启动后端

修改 `contest-admin/src/main/resources/application-dev.yml` 中的数据库连接信息：

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/contest_system?useUnicode=true&characterEncoding=utf-8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
    username: root
    password: your-password
```

编译并启动：

```bash
cd contest-system
mvn clean install -DskipTests
mvn spring-boot:run -pl contest-admin -am
```

后端启动后访问 **http://localhost:8080**。

### 3. 启动前端

```bash
cd contest-frontend
npm install
npm run dev
```

前端启动后访问 **http://localhost:3000**，开发服务器会自动将 `/api` 请求代理到后端。

- 两个按钮：浏览全部竞赛、立即加入（跳转登录/注册）

**② 轮播公告区域**
- 左右箭头切换公告焦点图
- 每张图可携带标题和描述文字
- 点击公告可跳转至关联链接（如竞赛详情页）

**③ 竞赛推荐区域**
- **热门竞赛**：按报名人数降序排列，展示当前最受欢迎的竞赛
- **最新竞赛**：按创建时间降序排列，展示最新发布的竞赛
- 每个竞赛以卡片形式展示：封面（按类别配色）、状态标签、名称、类别、报名人数、截止日期

> 首页底部的小字版权信息及平台简介。

#### 2. 浏览与筛选竞赛

**竞赛列表页** (`/contest`) 提供完整的搜索和筛选功能：

| 操作 | 说明 |
|------|------|
| **关键词搜索** | 在搜索框输入竞赛名称关键字，按回车或点击搜索按钮 |
| **类别筛选** | 下拉选择「理工类」「文史类」「艺术类」「体育类」「创新创业类」 |
| **状态筛选** | 可选「报名中」「已截止」「草稿」 |
| **参赛形式筛选** | 可选「个人赛」「团队赛」「均可」 |
| **排序方式** | 默认按更新时间、可选热门程度（报名人数）、报名截止日期 |
| **分页** | 每页 6 条，底部翻页 |

- 点击竞赛卡片进入**详情页**
- 卡片封面按类别有不同配色（理工=深蓝、文史=紫、艺术=红、体育=绿、创新创业=金）
- 卡片右下角显示参赛形式标签（个人赛/团队赛/均可）

#### 3. 竞赛详情页

竞赛详情页 (`/contest/:id`) 自上而下包括：

**顶部 Hero 区域**（按竞赛类别配色的动画背景）
- 状态标签（未发布/报名中/已截止）
- 竞赛名称
- 类别标签、级别标签、主办方标签
- 竞赛时间、地点、报名截止时间、已报名人数
- 参赛形式说明

**内容区域**（左右两栏布局）
- **左栏**：竞赛描述（富文本 HTML 渲染）、附件下载（如有）
- **右栏（操作区）**：
  - 竞赛状态为「报名中」时显示报名按钮
  - **个人赛**：显示「立即报名（个人赛）」按钮
  - **团队赛**：显示「团队报名」区域，列出用户已通过审核的团队供选择
  - **均可**：同时显示个人赛和团队赛两种报名方式（互斥，选择其中一种后隐藏另一种）

> ⚠️ 竞赛处于「草稿」状态时，学生看不到报名入口。已截止的竞赛会显示「已截止」状态标签。

#### 4. 个人报名流程

适用于 **contestType = 0（个人赛）** 或 **contestType = 2（均可）** 的竞赛。

| 步骤 | 页面 | 操作 | 注意事项 |
|------|------|------|---------|
| ① | 竞赛列表 | 找到目标竞赛，确认状态为「报名中」 | 卡片右上角绿色圆点 + 「报名中」标签 |
| ② | 竞赛详情 | 确认参赛形式包含「个人赛」 | 右栏有「立即报名」按钮 |
| ③ | 竞赛详情 | 点击**立即报名（个人赛）** | 弹出确认对话框 |
| ④ | — | 可选填写备注，点击确认提交 | 备注选填 |
| ⑤ | 我的报名 | 查看报名记录，状态为「待审核」 | — |
| ⑥ | — | 等待管理员审核 | — |
| ⑦ | 我的报名/通知 | 审核通过（状态变为「已通过」）或被驳回（显示驳回原因） | 可在「通知」中查看实时结果 |

**取消报名：**
- 在「我的报名」页面，点击「取消报名」
- 仅 **待审核** 和 **已通过** 状态的报名可取消
- 已驳回的报名不可取消

> ⚠️ **限制规则：**
> - 每人一个竞赛只能有一条有效报名记录
> - 不允许重复报名同一竞赛
> - 已满员的竞赛无法报名
> - 每人同时最多报名 **3 个竞赛**

#### 5. 团队管理（完整流程）

团队报名分四个阶段，涉及队长、队员、管理员三方协作：

##### 5.1 创建团队

| 步骤 | 说明 |
|------|------|
| ① | 导航栏点击**创建团队**，进入创建页面 |
| ② | 输入**团队名称**（必填项，不能为空，不能与其他团队重名） |
| ③ | 点击「创建」按钮提交，系统自动将创建者设为**队长** |
| ④ | 创建成功后自动跳转到**团队详情**页 |
| ⑤ | 页面顶部显示**6位邀请码**（由大写字母和数字组成），复制后分享给队友 |

> ⚠️ 一个学生可在不同竞赛中创建多个团队，但同一竞赛只能创建或加入一个团队。

##### 5.2 邀请成员加入

**方式一：通过邀请码加入（推荐）**

| 步骤 | 队长操作 | 队员操作 |
|------|---------|---------|
| ① | 在团队详情页复制**6位邀请码** | 向队长索要邀请码 |
| ② | 将邀请码通过微信/QQ发送给同学 | 进入**我的团队**页面 |
| ③ | — | 在「加入团队」输入框粘贴邀请码 |
| ④ | — | 点击「加入」按钮 |
| ⑤ | 在团队详情页的**入队申请列表**中看到新申请 | 等待队长审批 |
| ⑥ | 点击**批准**或**拒绝** | 收到通知告知审批结果 |

**方式二：重新生成邀请码**

如果邀请码泄露，队长可点击「重新生成」按钮刷新邀请码，旧码立即失效。

##### 5.3 管理成员

队长在**团队详情页**可执行以下操作：

| 操作 | 入口 | 说明 |
|------|------|------|
| **批准入队** | 入队申请列表 → 批准 | 队员状态变为「已通过」，团队人数 +1 |
| **拒绝入队** | 入队申请列表 → 拒绝 | 队员被拒绝加入 |
| **移除成员** | 已通过成员列表 → 移除 | 将已批准的成员移出团队，团队人数 -1 |
| **退出团队** | 团队详情页 → 退出（普通成员专用） | 成员自行退出，团队人数 -1 |
| **解散团队** | 团队详情页 → 解散（队长专用） | 解散整个团队，清退所有成员 |

##### 5.4 提交审核（队长操作）

当团队满足以下条件时，队长可提交团队给管理员审核：

- 团队至少达到竞赛的**最低人数要求**（竞赛详情中有标注）
- **已通过**的普通成员至少 1 人
- 团队状态必须为「组建中」（未提交过审核或上次被驳回后重新组建）

| 步骤 | 操作 |
|------|------|
| ① | 在团队详情页确认成员数和状态满足条件 |
| ② | 点击「提交审核」按钮 |
| ③ | 团队状态变为「已提交」，等待管理员审核 |
| ④ | 审核通过后，团队状态变为「已通过」，可进行团队报名 |
| ⑤ | 若被驳回，可查看原因，修改后重新提交 |

##### 5.5 团队报名（队长操作）

团队被管理员审核通过后，队长可进行团队报名：

| 步骤 | 页面 | 操作 |
|------|------|------|
| ① | 竞赛详情页 | 确认竞赛为团队赛且状态为「报名中」 |
| ② | 竞赛详情→右栏 | 在团队报名区域，从下拉列表中选择已通过的团队 |
| ③ | 竞赛详情 | 点击「立即报名」提交 |
| ④ | 我的报名 | 查看报名状态变为「待审核」 |
| ⑤ | — | 等待管理员审核报名 |
| ⑥ | 通知 | 收到报名审核结果通知 |

#### 1. 竞赛管理

> 路径：管理后台 → **竞赛管理** (`/admin/contest`)

##### 创建竞赛

| 字段 | 说明 | 约束 |
|------|------|------|
| **名称** | 竞赛全称 | 必填 |
| **类别** | 理工类/文史类/艺术类/体育类/创新创业类 | 必选 |
| **级别** | 校级/市级/省级/国家级 | 选填 |
| **主办方** | 举办单位名称 | 选填 |
| **竞赛时间** | 竞赛开始时间 | 必填，不能早于当前时间 |
| **报名开始时间** | 开始接受报名的时间 | 必填，不能早于当前时间 |
| **报名截止时间** | 停止接受报名的时间 | 必填，不能早于当前时间 |
| **地点** | 竞赛举办地点 | 选填，不填则显示「线上」 |
| **参赛形式** | 仅个人赛/仅团队赛/均可 | 必选 |
| **团队人数范围** | 最小人数 ~ 最大人数 | 参赛形式为团队类时必填 |
| **人数上限** | 最大报名人数，0 表示不限 | 选填 |
| **描述** | 竞赛详细介绍（支持富文本 HTML） | 选填 |
| **封面图片** | 竞赛封面图 URL | 选填（使用按类别配色渐变背景） |
| **附件** | 竞赛相关附件下载 | 选填 |

##### 编辑竞赛

- 点击竞赛列表中的**编辑**按钮，弹出编辑对话框
- **仅草稿状态**的竞赛可编辑
- 当竞赛有**待审核或已通过的报名记录**时，即使草稿状态也无法编辑
- 编辑后自动保存，不影响原有草稿状态

##### 发布竞赛

- 点击竞赛列表中的**发布**按钮
- 仅草稿状态的竞赛可发布 | 已发布的竞赛不可重复发布
- 发布后竞赛状态变为**报名中**（status = 1），学生可见并开始报名

##### 下架竞赛

- 点击竞赛列表中的**下架**按钮
- 仅报名中状态的竞赛可下架
- 有**已通过报名**的竞赛不可下架（需先处理关联报名）
- 下架后竞赛回到草稿状态

##### 删除竞赛

- 点击竞赛列表中的**删除**按钮
- **仅草稿状态**且**无任何报名记录**的竞赛可删除
- 删除后不可恢复

##### 竞赛状态流转

```
创建 ──→ 草稿 ──→ 发布 ──→ 报名中 ──→ (报名截止) ──→ 已截止
  ↑                ↑         │
  └── 删除 ────────┘         │
                  ┌───────────┘
                  ▼
               下架 → 回到草稿
```

#### 2. 报名审核

> 路径：管理后台 → **审核报名** (`/admin/review`)

##### 操作流程

| 步骤 | 操作 | 说明 |
|------|------|------|
| ① | 从顶部的**竞赛下拉列表**选择要审核的竞赛 | 列表按名称排序，支持搜索 |
| ② | 查看该竞赛的所有报名申请 | 显示报名人、报名类型、报名时间 |
| ③ | 可选按**状态**筛选（全部/待审核/已通过/已驳回） | 默认显示全部 |
| ④ | 点击「通过」按钮批准报名 | 确认后该学生报名成功 |
| ⑤ | 点击「拒绝」按钮并填写**驳回原因** | 原因不少于5个字符，学生会收到通知 |

> 报名审核通过后，该竞赛的**已报名人数**（currentCount）+1。

#### 3. 团队审核

> 路径：管理后台 → **用户管理** (`/admin/users`) — 团队审核通过 API 接口进行（`POST /api/team/{teamId}/admin-approve`）

##### 操作流程

| 步骤 | 操作 | 说明 |
|------|------|------|
| ① | 查看所有**已提交审核**的团队列表 | 显示团队名称、队长、人数、关联竞赛 |
| ② | 点击「通过」按钮批准团队 | 团队状态变为「已通过」，队长可进行团队报名 |
| ③ | 点击「驳回」按钮并填写原因 | 驳回后团队退回「组建中」状态，该团队关联的所有报名记录自动取消 |

> ⚠️ 驳回团队时，系统自动取消该团队的所有报名记录（包括已通过的），报名人数也会相应扣减。

#### 4. 用户管理

> 路径：管理后台 → **用户管理** (`/admin/users`)

| 操作 | 说明 |
|------|------|
| **查看用户** | 分页表格展示所有用户：学号、姓名、学院、专业、角色（学生/教师/管理员）、状态 |
| **新建用户** | 填写学号、密码、姓名、角色（学生/教师/管理员）、学院、专业；预设密码 `123456` |
| **编辑用户** | 修改姓名、角色、学院、专业等信息 |
| **冻结用户** | 点击冻结按钮 → 该账号无法登录系统 → 状态变为「已冻结」 |
| **解冻用户** | 点击解冻按钮 → 恢复该账号正常使用 |

- 管理员账号不可被冻结
- 列表支持按用户名或学号搜索
- 管理员编辑用户时可修改角色字段（学生 ↔ 教师 ↔ 管理员）

#### 5. 内容管理（CMS）

> 路径：管理后台 → **内容管理** (`/admin/cms`)

##### 轮播图管理

| 操作 | 说明 |
|------|------|
| **创建** | 上传图片，设置标题、排序权重、跳转链接、展示位置 |
| **编辑** | 修改已有轮播图的图片、标题、链接 |
| **删除** | 移除轮播图 |

- 轮播图出现在首页 Hero 区域下方，支持左右箭头切换
- 按 `sort_order` 字段升序排列展示
- 支持选择展示位置（如「首页轮播」「公告中心」）

##### 公告管理

| 操作 | 说明 |
|------|------|
| **创建** | 使用**富文本编辑器**编写公告内容（支持图文混排、表格、链接等），设置标题 |
| **编辑** | 修改已有公告的内容和标题 |
| **删除** | 移除公告 |

- 公告支持**发布/取消发布**控制，发布的公告才在首页显示
- 公告出现在首页轮播图下方的公告区域

#### 6. 通知管理

> 路径：管理后台 → **通知管理** (`/admin/notification`)

| 操作 | 说明 |
|------|------|
| **发送定向通知** | 选择指定用户（按用户ID或用户名搜索），填写标题和内容，点击发送 |
| **系统广播** | 无需选择用户，填写标题和内容后广播给所有用户 |

- 通知发送后，目标用户的「通知角标」会实时更新
- 通知内容支持纯文本格式

#### 7. 权限管理（New）

> 路径：管理后台 → **权限管理** (`/admin/permissions`)

支持按角色和按用户两种维度的权限分配：

| 标签页 | 说明 |
|--------|------|
| **按角色分配** | 选择角色（学生/教师/管理员），勾选该角色拥有的权限，点击保存 |
| **按用户分配** | 搜索用户，点击「分配权限」，单独为用户授予额外权限 |

- 权限项包括：竞赛创建/编辑/删除/发布、用户列表/创建/冻结、报名审核/列表/取消、团队审核/列表、通知发送/广播、CMS管理、日志查看、文件上传、权限分配
- 按用户分配的权限与按角色分配的权限取**并集**

#### 8. 操作日志

> 路径：API 接口 `GET /api/log/page`（后端支持，无前端页面，可通过 Swagger/API 工具查看）

| 信息 | 说明 |
|------|------|
| **操作人** | 执行操作的管理员用户名 |
| **操作类型** | 创建竞赛、审核报名、审核团队、冻结用户等 |
| **操作详情** | 具体的操作内容描述 |
| **IP 地址** | 操作时的客户端 IP |
| **操作时间** | 精确到秒的操作时间 |

- 日志按时间倒序排列，最新的在最前面
- 日志不可删除，用于审计追溯

## 开发指南

### 编码规范

- **后端**：BDD 风格测试方法命名（如 `registerPersonal_shouldThrowWhenContestNotFound`），AAA 模式（Arrange-Act-Assert），单用例单断言
- **前端**：Vue 3 Composition API + `<script setup>`，Element Plus 组件，Pinia 状态管理
- **API 响应**：统一 `Result<T>` 封装，包含 `code`（200=成功, 400=业务错误, 500=服务端错误）、`message`、`data`

### 代码风格

- 生产代码不加注释
- 关键路径保证类型安全
- 新增功能遵循现有模式
- 新组件参考已有实现了解约定

### 安全机制

- 密码使用 Hutool BCrypt 加密存储
- JWT Token 7 天过期，密钥通过 `contest.jwt.secret` 配置（位于 `application.yml`）
- 基于角色的访问控制（学生=0, 管理员=1, 教师=2）
- 前端富文本内容经 XSS 过滤器（`sanitizeHtml`）去除 `<script>`、`<iframe>`、事件处理器等危险标签
- MyBatis-Plus 参数化查询防止 SQL 注入
- 全局异常处理器覆盖参数校验、认证鉴权、数据完整性错误

### Maven 构建

```bash
# 开发模式（默认）
mvn spring-boot:run -pl contest-admin -am

# 生产打包
mvn clean package -DskipTests -Pprod
```
